# 放置禁止区域の作図手順（ZONE-DIGITIZING）

Tier A（区域ポリゴン）を増やすための手順書。
**誰が作図しても精度区分の意味がぶれないこと**を目的とする。

---

## 0. まず読むこと

Ring は「その場所に自転車を停めたら撤去されるか」を答えるアプリである。
作図した区域が実際と違えば、利用者は撤去され、平日昼間に保管所へ取りに行くことになる。

- **分からない部分を「たぶんこの辺」で塗らない。** 分からないなら作図しない
- **精度区分を高く見せない。** 迷ったら低いほうを選ぶ
- **出典 URL と確認日を必ず残す。** 出典を持たないデータは Ring に載せない

---

## 1. 精度区分（`accuracy`）の判定基準

| 値 | 使ってよい条件 | 想定誤差 | 判定確度 |
|---|---|---|---|
| `traced` | 区が公開する区域図（PDF・画像・GIS 画面）の**境界線そのもの**を、地図に重ねてトレースした | 概ね 10m 以内 | `high` |
| `described` | 条例別表・区の文章による区域記述（町丁目名・道路名）から作図した。境界となる道路が特定できている | 道路 1 本分程度 | `medium` |
| `estimated` | 上記のいずれでもない。駅の位置と指定有無から機械的に生成した円など | 数十〜数百m | `low` |

### 迷ったときの判断

- 区域図の一部だけがはっきり読めて、残りが読めない → **その区域は作図しない**（一部だけ `traced` にしない）
- 区域図はあるが縮尺・方位が分からない → `described` にはできない。作図しない
- 「◯◯駅の周辺 200m」と区が書いている → `described`（記述に基づくため）

---

## 2. 手順

### 2.1 出典を確定する

区の公式ページで、区域図そのものの URL を控える。

- 区域図のページ URL（人が見るページ）
- 画像・PDF の直接 URL
- ページに書かれた**施行日**（「令和7年10月1日から」など）
- 確認した日

`data/manual/ward-links.json` に区のページが登録済みかを確認し、無ければ追加する。
**実在を確認した URL だけを登録する。** リンク切れは利用者の不信につながる。

### 2.2 地図に重ねてトレースする

1. [geojson.io](https://geojson.io/) を開く
2. 背景を地理院タイルに合わせる（Ring と同じ基図で作図するとズレが減る）
3. 区域図と見比べながら、**境界となっている道路の中心線**に沿って多角形を描く
4. 区域図が「赤線上および赤線内の公道」と書いている場合、赤線そのものが境界である

**注意**

- 区域図は駅ごとに分かれていることが多い。**1 つの駅周辺を 1 つの Feature** にする
- 区域が飛び地になっている場合は MultiPolygon にする
- 内側に除外区域（穴）がある場合は、Polygon の 2 番目以降のリングとして表現する。
  判定エンジンは穴を正しく扱う（テスト T-15 で保証している）

### 2.3 プロパティを埋める

`data/manual/zones-traced.geojson` に FeatureCollection として保存する。

```jsonc
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": { "type": "Polygon", "coordinates": [[ /* ... */ ]] },
      "properties": {
        "id": "zone-a-chiyoda-akihabara",       // zone-a-{区}-{場所}
        "tier": "A",
        "name": "秋葉原駅・岩本町駅周辺放置禁止区域",
        "municipality": "千代田区",
        "stations": ["秋葉原", "岩本町"],        // ★ 重要。下記 2.4 参照
        "status": "active",                      // active / planned / expired
        "effective_from": "2020-04-01",
        "effective_to": null,
        "accuracy": "traced",
        "source_name": "千代田区「自転車等放置禁止区域の案内図」",
        "source_url": "https://www.city.chiyoda.lg.jp/koho/machizukuri/kotsu/jitensha/kinshikuiki.html",
        "source_format": "区域図（画像）をトレース",
        "verified_at": "2026-08-23",
        "notes": null
      }
    }
  ]
}
```

### 2.4 `stations` を必ず正しく入れる ★

`stations` は **Tier B の推定リングを抑止するキー**である（`docs/DECISIONS.md` D-05）。

ここに書いた駅は、Tier B の対象から外れる。
つまり「精密に作図した区域の外」と判定した地点が、粗い円で「内かも」と塗り潰されなくなる。

- 駅名は **「駅」を含めない**（`秋葉原` であって `秋葉原駅` ではない）
- `public/data/stations.json` の `name` と一致させる
- **その区域図がカバーしている駅をすべて書く。** 書き漏らすと、その駅では推定リングが残り続ける
- 逆に、区域図でカバーしていない駅を書いてはいけない。その駅の判定が消える

### 2.5 取り込んで確認する

```bash
npm run etl        # zones-traced.geojson が取り込まれる
npm test           # 判定エンジンのテスト
npm run dev        # 地図で実際に見る
npm run verify     # スマホ幅の実ブラウザで確認
```

ETL のログに `Tier A（作図ポリゴン）N 件` と出れば取り込まれている。

**確認すること**

- [ ] 地図上の多角形が、区の区域図と同じ形になっているか
- [ ] 区域の内側で判定が `inside` になり、「推定」バッジが消えているか
- [ ] 区域のすぐ外で `near` になり、境界までの距離が妥当か
- [ ] 区域の外で `outside` になり、`likely`（推定）に戻っていないか ← `stations` の記入漏れの検出
- [ ] 判定カードの出典が、その区の区域図ページを指しているか

## 3. 施行前の区域を追加する場合

区が「令和8年4月1日から拡大」と告知している場合：

1. `data/manual/zone-changes.json` に変更を記録する（出典 URL と確認日つき）
2. 拡大後の区域図が公開されているなら、`zones-traced.geojson` に
   `status: "planned"` / `effective_from: "2026-04-01"` で作図する
3. ETL が planned 区域として取り込み、判定カードに「◯年◯月◯日から撤去対象になります」が出る

施行日を過ぎたら `status` を `active` に変える（`npm run promote` で自動化予定）。

---

## 4. やってはいけないこと

- ❌ 区域図が読めない部分を想像で埋める
- ❌ 精度を実際より高く申告する（`estimated` を `described` と書くなど）
- ❌ 出典 URL を推測で書く（存在を確認していない URL を載せない）
- ❌ `stations` を空にする（Tier B と二重判定になる）
- ❌ 他人の作図データを出典なしに取り込む

---

## 5. Tier A が 0 件である理由（2026-08-23 時点）

千代田区・文京区・港区の公式ページを確認したところ、
区域は**駅ごとの地図画像（JPG / PNG）としてのみ公開**されており、
町丁目や街路名による文章記述も、条例の別表も存在しなかった。

画像からのトレースは技術的には可能だが、
**縮尺と方位が明示されていない画像を正確に georeference する作業**が必要で、
誤差を 10m 以内に収められる保証がない。

そのため Ring は、精度を偽って `traced` を名乗るのではなく、
**Tier A を 0 件のまま公開し、その事実を画面に明記する**という選択をした。

同時に、区へ機械可読なデータの公開を依頼する文面を生成する機能（spec.md FR-9）を実装している。
**区がデータを公開すれば、この手順書は不要になる。それが本来あるべき姿である。**
