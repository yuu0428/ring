# データ出典とライセンス（DATA）

Ring が使っているデータの一覧と、その取得方法・ライセンス・注意点。
調査・取得日は **2026-08-23**。

アプリ内の「データについて」画面も、同じ内容を `public/data/sources.json` から表示している。

---

## 1. 最初に確認したこと：放置禁止区域のデータは存在しない

このプロジェクトの成否を分ける調査を最初に行った。結論は次のとおり。

| 調べた場所 | 結果 |
|---|---|
| 東京都オープンデータカタログサイト（CKAN 全文検索） | 「禁止区域」に該当するデータセット **125 件**を確認。自転車の放置禁止区域は **0 件** |
| 杉並区「自転車放置禁止区域」（カタログに唯一登録されていた CSV） | 登録 URL が **404**。すぎナビ（区の地図システム）ごと到達不能 |
| 千代田区「自転車等放置禁止区域の案内図」 | 11 の駅周辺を **JPG / PNG 画像**でのみ公開。文章による境界記述なし |
| 文京区「自転車等の放置禁止区域について」 | 16 の駅周辺＋重点整理区域 2 か所を **画像**でのみ公開 |
| 港区「自転車等の放置禁止区域」 | 駅名の列挙と **PNG 画像**のみ。町丁目・街路名の記載なし |
| 各区の例規集（条例施行規則の別表） | 境界を文章で定義した別表は見つからず |

**区は区域図を持っているのに、機械が読める形では公開していない。**
これが本企画最大の障害であり、同時に企画の中身でもある。

→ この事実が、区域データを **Tier A / Tier B の 2 階層**で持つ設計（`docs/DECISIONS.md` D-04）の根拠になった。
→ アプリには、区へ公開を依頼する文面を生成する機能（spec.md FR-9）を入れている。

## 2. 使用しているデータセット

### 2.1 放置禁止区域の指定有無 —— このプロジェクトの根幹

| 項目 | 内容 |
|---|---|
| **データ名** | 駅別放置自転車の状況（令和7年度） |
| **提供元** | 東京都都民安全総合対策本部 |
| **ページ** | https://www.tomin-anzen.metro.tokyo.lg.jp/kotsu/jitensha/houchi/0000001962 |
| **ファイル** | https://www.tomin-anzen.metro.tokyo.lg.jp/documents/d/tomin-anzen/07ekibetsuhouchi |
| **形式** | XLSX（838 行） |
| **ライセンス** | 東京都オープンデータカタログサイト利用規約（CC BY 4.0 相当） |
| **用途** | **放置禁止区域の指定有無**、駅別の放置台数、収容能力 |

この Excel の駅名欄には `＊` の印があり、凡例にこう書かれている。

> （注）＊印がある駅周辺には自転車等駐車場が整備され、放置禁止区域が指定されている。

**全都 53 自治体・663 行・702 駅を網羅する、唯一の公式かつ機械可読な指定情報。**
Ring が「代表区のデモ」ではなく「東京全域で答えが返るサービス」になったのは、このデータによる。

**扱う際の注意**

- 印刷ページごとに**見出し行が 28 回繰り返される**。除外しないと駅名として取り込まれ、自治体の対応まで崩れる
- 注記行も印刷ページごとに繰り返される
- 「東京駅」のように**複数の区市町村に計上される駅**がある。上書きすると最後の区の値だけが残るため、台数は合算する
- 1 行が「有楽町駅、日比谷駅」のように複数駅を含むことがある

### 2.2 駅の座標

| 項目 | 内容 |
|---|---|
| **データ名** | 国土数値情報 鉄道データ N02-24（2024年） |
| **提供元** | 国土交通省 |
| **ページ** | https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2024.html |
| **ファイル** | https://nlftp.mlit.go.jp/ksj/gml/data/N02/N02-24/N02-24_GML.zip |
| **形式** | Shapefile / GeoJSON（全国 10,235 駅） |
| **ライセンス** | 国土数値情報利用約款 |
| **用途** | 駅の位置、路線名、事業者名 |
| **表記** | 「国土交通省 国土数値情報（鉄道データ）」 |

**扱う際の注意**

- 駅はプラットフォームの**線分（LineString）**として格納されている。Ring は線分の重心を駅位置としている
- 同名の駅が路線ごとに複数入っている。座標を平均して 1 駅に集約する
- 東京都域は bbox（経度 138.9–139.95 / 緯度 35.48–35.92）で抽出し、931 駅

**都 Excel との突合率は 99.9%（702 駅中 701 駅）。**
残りは `data/manual/station-aliases.json` の別名表で吸収している
（`霞が関`→`霞ケ関`、`二重橋`→`二重橋前`、`つくばエクスプレス浅草`→`浅草` など）。

### 2.3 駐輪場（159 件 / 6 区）

| 提供元 | データ名 | 件数 | 形式 |
|---|---|---|---|
| 文京区 | 自転車駐車場 | 36 | CSV (CP932) |
| 品川区 | 区営自転車駐輪場 | 26 | CSV (CP932) |
| 品川区 | 民間自転車駐輪場 | 16 | CSV (CP932) |
| 目黒区 | 自転車等駐輪場一覧 | 49 | CSV (CP932) |
| 中野区 | 区営自転車駐車場設置箇所 | 27 | CSV (UTF-8 BOM) |
| 中央区 | 区営二輪車駐車場一覧 | 5 | CSV (CP932) |

いずれも東京都オープンデータカタログ経由で公開。ライセンスは CC BY 4.0。

**扱う際の注意**

- **区ごとに列名も料金表記も全く違う。** 区ごとのアダプタで 1 つの形に寄せている
- 料金は「1回100円」「24時間毎に150円」「100円/時、9時間を越える場合は、定額1,000円」など表記がばらばら。
  **無理に数値化せず原文のまま保持する**（`docs/DECISIONS.md` D-10）。誤った数値より正確な原文のほうが役に立つ
- 中央区の CSV は引用符内に改行を含む。行数と件数が一致しない
- 世田谷区「公営駐輪場一覧」（55 件）は**緯度経度の列が空**のため未取り込み。住所からの座標付与が必要

### 2.4 撤去自転車保管所（8 件 / 2 区）

| 提供元 | データ名 | 件数 | 特徴 |
|---|---|---|---|
| 大田区 | 保管所一覧 | 4 | **撤去駅（区域内撤去）の列があり、駅と保管所の対応が分かる** |
| 中野区 | 区営自転車保管場所設置箇所 | 4 | 撤去区域の列があり、対応する駅が分かる |

**扱う際の注意**

- 開所時間は「月曜日～土曜日／第2・第4日曜日（祝日、12月29日~1月3日を除く）」のような日本語で、機械判定できない。
  Ring は**確認できたものだけ**を `open_rule` として構造化し、それ以外は「今日は開いているか」を表示しない
  （`docs/DECISIONS.md` D-11）。推測して「開いています」と出すと、ユーザーは無駄足を踏む
- 中野区のデータには同一保管所の重複行がある

保管所データを公開していない区については、アプリは区の公式ページへ誘導する。
リンクは `data/manual/ward-links.json` に、**実在を確認したものだけ**を登録している。

## 3. Ring が生成したデータ

| 項目 | 内容 |
|---|---|
| **データ名** | 放置禁止区域データ（Ring 生成） |
| **ファイル** | `public/data/zones.geojson` |
| **形式** | GeoJSON |
| **ライセンス** | **CC BY 4.0**（自由に利用可） |
| **精度** | 現在はすべて `estimated`（推定） |

各 Feature は次を必ず持つ。

- `tier` … `A`（作図ポリゴン）/ `B`（駅指定リング）
- `accuracy` … `traced` / `described` / `estimated`
- `source_name` / `source_url` / `source_format` / `verified_at`
- `radius_m` … Tier B の推定半径

**現在 Tier A は 0 件。** 作図元となる公開データが存在しないため。
`data/manual/zones-traced.geojson` に置けば自動で取り込まれる（手順は `docs/ZONE-DIGITIZING.md`）。

## 4. 取得方法

```bash
npm run etl
```

- 取得結果は `.cache/` に保存され、取得に失敗した場合はキャッシュで継続する
- 出力は `public/data/` に整形 JSON で書かれ、**リポジトリにコミットする**
- ビルド時に外部から取得しない（`docs/DECISIONS.md` D-09）

**なぜコミットするのか。**
調査中、複数の公式 URL が 404・ホスト移転・アクセス拒否を返した。
ビルド時に外部から取りに行く設計にすると、区のサイトの都合でこちらのサイトが壊れる。

週次で ETL を回して差分を検出する GitHub Actions（`.github/workflows/data-refresh.yml`）を用意しているが、
**自動マージはしない。** データの正しさは人が確認するべきものだから。
